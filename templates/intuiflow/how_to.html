1. System Overview

The Intuiflow Integration keeps Fishbowl and Intuiflow synchronized. It handles four jobs: importing new orders from Intuiflow into Fishbowl, updating existing work orders with the latest Intuiflow scheduling data, closing completed work orders (cycling inventory in the process), and uploading fresh Fishbowl data back into Intuiflow so its scheduling engine has accurate inputs.

Key Features:

  • Two schedulable sync pipelines (Full Sync and Partial Sync)
  • Four individual modules that can be run on demand at any time
  • Per-pipeline and per-module email notifications
  • Short inventory alerts when a work order cannot be closed due to missing parts
  • Invalid default location alerts when a work order is skipped due to a part with no default location set
  • Full run history and error logs per pipeline and module

2. Sync Pipelines

Pipelines chain multiple modules together in a fixed order. They are the recommended way to keep the two systems in sync and are the only items that can be put on an automatic schedule.

Full Sync

Runs all four modules in order:

  1. Import Pending Orders — pulls approved Intuiflow orders and creates MOs/POs in Fishbowl
  2. Update Work Orders — updates open Fishbowl MOs with current Intuiflow scheduling data
  3. Close Work Orders — closes completed Intuiflow WOs in Fishbowl, cycling inventory
  4. Upload FB Files — sends six Fishbowl datasets back to Intuiflow for scheduling
Use Case: Run this when you need everything brought into sync — new orders, schedule updates, closures, and data upload all at once. Typically scheduled to run overnight or at an interval during working hours.

Partial Sync

Runs two modules in order:

  1. Update Work Orders
  2. Close Work Orders
Use Case: A lighter, faster sync for keeping existing work orders up to date and closing completed ones without re-importing orders or uploading files.
Note: If a single module fails inside a pipeline, the remaining modules still run. The pipeline status will show Last run: Error if any module encountered a problem, even if others succeeded.

3. Individual Modules

Individual modules can be run on demand at any time but cannot be scheduled. Use them when you need to run just one piece of the sync process — for example, to re-upload Fishbowl files without re-importing orders.

Import Pending Orders

Fetches orders from Intuiflow that have been approved and are pending creation in Fishbowl. For each one, it creates the corresponding Manufacturing Order (MO) or Purchase Order (PO) in Fishbowl and then marks the order as committed in Intuiflow.

Update Work Orders

Looks at all open Fishbowl MOs that are linked to Intuiflow work orders and updates them with the latest scheduling data from Intuiflow — quantities, dates, routing names, and other fields. Also handles work orders that have been closed in Intuiflow but are still open in Fishbowl, and cleans up records for orders closed in Fishbowl that Intuiflow still considers open.

Close Work Orders

Takes work orders that Intuiflow has marked as complete and closes them in Fishbowl. Closing a work order cycles inventory — finished goods are added to stock and raw materials are consumed. If there is not enough inventory on hand to fulfill a cycle, the order is skipped and an optional short inventory alert can be sent.

Upload FB Files

Queries Fishbowl for six datasets — demand history, parts, bill of materials, supply orders, demand orders, and inventory — and uploads each one to Intuiflow via its import API. This gives Intuiflow the data it needs to generate an accurate production schedule.

4. Running a Pipeline or Module

Every card on the dashboard has a ▶ Run Now button. Clicking it starts that pipeline or module immediately, regardless of any schedule.

1

Click ▶ Run Now on the card you want to run.

2

The status badge changes to Running... and the button is disabled while it executes.

3

When it finishes, the badge updates to Last run: Success or Last run: Error and the last run time is updated.

Note: A pipeline or module cannot be run while it is already running. The Run Now button will remain disabled until the current run completes. Runs triggered manually and runs triggered by the scheduler do not conflict — if a scheduled run starts while you are already running the same pipeline manually, the scheduler will skip that fire.

5. Scheduling

Only the two pipelines (Full Sync and Partial Sync) can be scheduled. Individual modules are run on demand only. To configure a schedule, click a pipeline card to expand it, then click the Schedule tab. Toggle Scheduled on to reveal the scheduling options.

Every N Minutes

Runs the pipeline repeatedly at a fixed minute interval. The interval is anchored to the last run time, so restarting the server does not reset the clock.

Daily

Runs once per day at a chosen time. If the server is down at the scheduled time, the next run will be the following day at that time.

Weekly

Runs once per week on a chosen day and time.

Custom (Cron)

Enter a standard cron expression for full control over the schedule. Format: minute hour day month day_of_week. Example: 0 6 * * 1-5 = Mon–Fri at 6:00 AM.

Tip: Click Save Schedule after making any changes. The Next: time shown in the card header will update immediately to confirm the new schedule was applied.

6. Notifications

Every pipeline and individual module has its own notification settings, configured independently. Click any card to expand it, then click the Notifications tab. Note that pipeline notification settings are completely separate from individual module notification settings — configuring Full Sync notifications does not affect the Close Work Orders module notifications, and vice versa.

Notify Me Options:

  • Off No emails are sent.
  • After every run An email is sent after every run, whether it succeeded or failed.
  • On failures An email is only sent when a run encounters an error.

Managing Recipients:

Add email addresses one at a time using the Recipients field and click + Add (or press Enter). Remove any recipient by clicking the × on their chip. Click Save Notifications when done.

Note: Notification emails are branded Radian emails and include the run status, timestamp, and a full breakdown of what each module did — including which records were updated, created, or skipped.

7. Short Inventory Alerts

When the Close Work Orders step runs — either as part of a pipeline or on its own — it checks whether there is enough inventory on hand to cycle each work order. If a work order cannot be closed because a required part is short, that order is skipped and can be flagged via a separate short inventory alert email.

How to enable short inventory alerts:

1

Open the Full Sync, Partial Sync, or Close Work Orders card and go to the Notifications tab.

2

Scroll down to the Short Inventory Notifications section and set Short Inv Alerts to On.

3

Add the email addresses that should receive these alerts in the Short Inv Recipients field.

4

Click Save Notifications.

Important: Short inventory alerts are configured and sent independently for each card. Enabling them on Full Sync does not automatically enable them on Partial Sync or the Close Work Orders module — each must be configured separately. The alert email lists each skipped work order and the specific part(s) that were short.

8. Invalid Default Location Alerts

When the Close Work Orders step runs — either as part of a pipeline or on its own — it checks whether each part on every work order has a valid default location set in Fishbowl. If a part is missing a default location, the order cannot be closed and it is skipped. An optional alert email can be sent listing each affected work order and the specific part(s) that need a default location assigned.

How to enable invalid default location alerts:

1

Open the Full Sync or Partial Sync card and go to the Notifications tab.

2

Scroll down to the Invalid Default Location Notifications section and set Invalid Default Locations Alert to On.

3

Add the email addresses that should receive these alerts in the Invalid Default Location Recipients field.

4

Click Save Notifications.

Important: Invalid default location alerts are configured and sent independently for Full Sync and Partial Sync. Enabling them on one does not enable them on the other — each must be configured separately. The alert email lists each skipped work order and the specific part(s) that need a default location assigned in Fishbowl.

9. Logs & Run History

Every pipeline and module keeps its own run history. Click a card to expand it, then click the Logs tab. Two panels are shown: Recent Errors and Recent Logs.

Recent Errors

Shows only runs that encountered an error, with a breakdown of which step failed and what went wrong. Up to 10 entries are kept.

Recent Logs

Shows all runs (including successful ones) with the full log output from that run. Up to 10 entries are kept.

Buttons:

  • Refresh — reloads the log panel from the server.
  • Clear All — permanently deletes the log history for that panel.
Tip: Logs are loaded on demand when you open the Logs tab. Use Refresh if a run just completed and you want to see the latest entry without reloading the page.
